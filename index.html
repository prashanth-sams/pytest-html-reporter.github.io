Quickstart

Three minutes to your first report

Nothing to register, nothing to import. Add the package, run pytest, and the report is waiting in report/ — and on a local run it opens by itself.

  1. Install

    One package. It registers itself with pytest through an entry point.

  2. Run your suite

    No flags needed. Add --html-report only if you want a different path, filename or title.

  3. Open the page

    A single HTML file you can email, attach to a ticket, or publish to Pages as-is.

Full getting-started guide
shell 
$ pip3 install pytest-html-reporter
$ pytest tests/

# -> ./pytest_html_report.html
shell 
$ pytest tests/ --html-report=./report/report.html --title='PYTEST REPORT'

# strftime placeholders give each run a folder of its own
$ pytest tests/ --html-report=./reports/%Y%m%d/report_%H%M.html
ini 
[pytest]
addopts = --html-report=./report --title='Nightly'
report_screenshots = failed
It opens itself On a local run the finished report is opened in your browser. On a build agent it stays quiet — CI is detected, not guessed at.
What is in the page

Everything a failing build makes you ask

A pass/fail count tells you how much went wrong. The rest of the report tells you what went wrong, whether it has been going wrong for a while, and where to look next.

Overview & trends

Totals, pass rate, run duration, the environment the suite ran in, the most-failed suite, and the failure delta since the last build.

Why this run failed

Failures grouped by the exception each came out of, biggest group first — 12 failures, 9 are TimeoutException — with the share of the run each group holds and how it has moved since last build.

Test steps

The named, timed pieces a test is made of, nested from the suite down to the test to what it actually did — with the failing step carrying the screenshot that explains it.

Automatic screenshots

A test that fails while holding a Selenium driver or a Playwright page is photographed for you. No hook, no fixture, no import, no conftest.py.

Archives & history

Every previous build kept in the same page, with retention by count, by age or by date. Flaky tests and standing failures are read straight out of that history.

Deep links

Every test row has an address of its own. Copy it from the button beside the failure and it opens the report on that row, whatever page of the table the sort has put it on.

The ecosystem

Three projects, one report

The plugin writes the report. The Action publishes it from CI and comments on the pull request. The extension puts the same results in your editor sidebar.

pip package

pytest-html-reporter

The pytest plugin that generates the report.

  • Analytics across every archived build
  • Screenshots, steps, logs, coverage

GitHub Action
