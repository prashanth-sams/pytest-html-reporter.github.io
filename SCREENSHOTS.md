# Screenshots the documentation is waiting for

Generated by `python3 tools/shots.py` — do not edit by hand.

**61 outstanding** (3 of them animated) across 15 page(s).

## Already captured, not yet wired in

`assets/img/shots/captured/` holds screenshots taken from a real generated report —
all nine tabs, in light and dark, at 1600x1000 and 2x pixel density:

`dashboard`, `analytics`, `suites`, `test-metrics`, `test-steps`, `archives`,
`screenshots`, `api-logs`, `coverage` — each as `<tab>-light.png` and `<tab>-dark.png`.

They are **staged, not used**. Two things want a decision first:

1. **The sidebar carries the sponsor lockup** the local build renders. Whether that
   belongs on the documentation site is an editorial call.
2. **The Dashboard shot came from a one-test run**, so it undersells the page. Analytics
   is the opposite — it reads every archived build and looks excellent.

To use one: re-run the suite so the last build is representative, re-capture, move the
file into `assets/img/shots/`, then swap its `<figure class="imgslot">` for a
`<figure class="shot">`.

To re-capture, serve the report and drive it: every tab is at `#dashboard`, `#analytics`,
`#suites`, `#test-metrics`, `#test-steps`, `#archives`, `#screenshots`, `#api-logs` and
`#coverage`, and `#themeSwitch` toggles the theme.

## How to fill one in

1. Take the picture described below.
2. Save it as `assets/img/shots/<filename>` using exactly the filename given.
3. In `content/<page>.html`, replace the whole `<figure class="imgslot">…</figure>`
   block with:

   ```html
   <figure class="shot">
     <img src="../assets/img/shots/<filename>" alt="<what it shows>" loading="lazy">
     <figcaption><the caption></figcaption>
   </figure>
   ```

4. Run `python3 tools/build.py`.

Shoot at **1440px wide** unless a row says otherwise, and take the light and dark
versions of anything theme-dependent — the site swaps images per theme only if you
add a second `<img>`, so pick the theme that reads best if you take just one.
